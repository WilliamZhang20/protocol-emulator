# USB low-speed transaction milestone

Status: packet TX/RX plus a transaction reference model. **The PX8 device
transaction engine is not implemented yet.** Enumeration is a later milestone.
Existing RTL is unchanged. This branch does not establish USB compliance.

## What works and how it is tested

`test/cocotb_tests/test_usb.py` drives and observes the chip's top-level pins in
Verilator. Packet tests independently encode/decode NRZI, stuffing, CRC16 and
EOP, exercise maximum eight-byte payloads, clock mismatch and jitter, and reject
bad CRC. The overflow regression deliberately stops host reads during a packet:
the old program returned success despite losing bytes; the updated program
checks the shifter's sticky overrun flag before reporting success. All 14 USB
RTL tests pass. Random payload fixtures now advance their generator rather than
recreating it for every byte.

`tools/usb_transactions.py` is an independent packet-level oracle with explicit
buffers, not microcode and not evidence that transactions fit on the chip.
Its tests cover token CRC5 (including literal USB-IF examples), address/endpoint
routing, PID complements, DATA CRC16, IN retry until ACK, OUT duplicate suppression,
NAK under backpressure, STALL, SETUP supersession and DATA1 initialization,
invalid packets and explicit timeout. Run `make tooling-test` (12 tests total,
including the pre-existing tooling tests).

## What the existing receiver cannot do

The existing receiver streams the complete packet, including SYNC/PID/CRC, to
the host. A maximum DATA packet has 12 bytes including SYNC, exceeding the
four-entry RX FIFO plus two byte buffers and the shifter's pending word. With
no host drain it demonstrably overruns. Checking the error fixes the verdict,
not the buffering capacity. SETUP needs eight bytes accepted atomically, and
OUT must not expose an accepted application packet before validation.

This proves a limit of this particular receive program and host-drain contract,
not that the architecture cannot implement USB. PX8 cannot write received bytes
to SRAM, but alternative use of existing FIFO/register resources must be assessed
before proposing hardware changes. Static SRAM data can potentially support IN
retransmission; dynamic host-fed IN data needs an explicit retention strategy.

## Required next implementation and acceptance tests

Implement a resident, configured-address endpoint-zero transaction program;
retain IN payload until valid ACK, and commit OUT/SETUP exactly once after
validation. Measure the emitted image against 1024 bytes, enumerate live storage
and tile/context allocations, and test with the host stalled. A host-assisted
reply is insufficient unless its latency is bounded inside the same contract.

Drive token/data/handshake packets through the DUT pins and compare responses
and delivered application bytes against the oracle. Include zero/eight-byte
payloads, lost ACK and retry, duplicate OUT, full buffers, new SETUP while busy,
wrong address/endpoint, invalid PID/CRC/stuffing/EOP, timeouts and bus ownership.
The model's `framing_valid` flag is not a substitute for these wire tests.

Measure turnaround from the preceding EOP SE0-to-J edge to response SOP J-to-K:
use the conservative 2–6.5 bit-time window (64–208 cycles at 48 MHz/32 cycles per
bit). Verify ACK timeout at 16–18 bit times and test boundary conditions, not
just nominal timing. These are future acceptance checks, not results obtained
by the current packet tests. Reset/enumeration/descriptors are not implemented.

Sources: [USB 2.0 specification](https://www.usb.org/document-library/usb-20-specification),
sections 7.1.18.1, 7.1.19.1, 8.5.3 and 8.6;
[USB-IF CRC examples](https://www.usb.org/sites/default/files/crcdes.pdf).

## Previous protocol verification and performance

Before this change, the combined UART/SPI/I2C/USB/Ethernet/CAN RTL suite passed
42 tests at revision 58da19f. UART checks byte values and bit timing; SPI uses a
reference slave across all four modes and tests FIFO starvation; I2C checks
ACK/NACK, repeated START, stretching and open-drain behavior. Ethernet checks
Manchester timing, FCS, link pulses and RX rejection; CAN tests CRC/stuffing,
RX ACK and clock mismatch, without establishing a complete arbitrating node.

Performance evidence is cycle/timing assertions in those tests. It is not a
comprehensive throughput/latency benchmark or fresh physical signoff. Module
formal proofs and bounded checks supplement simulation, but there is no existing
whole-USB-transaction formal proof. Compiler UART integration separately checks
actual generated bytecode on RTL; it does not implement USB compilation.
