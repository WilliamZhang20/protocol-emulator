# Paired shifter block experiment

This is a standalone comparison of block contracts, not the chip top, an
implementation of the proposed fabric, or a compiler-produced configuration.
Run `make tile-shift-pair-experiment`. The RTL test is standalone and is not in
`COCOTB_TEST_MODULES`; it does not alter gate-level cocotb coverage.

All three candidates expose the same pair of serial inputs/outputs, starts,
step events, sample events, widths, bit orders, payload words, busy/done and
`compatible` status. Width and bit order are assumed static during a transfer.
Values for MSB-first transmission are left aligned; LSB-first starts at bit 0.
Each lane has separate data and receive state.

* `pair_separate`: two independent shifters, including start/step/width and
  sequencers.
* `pair_combined_shared`: two data lanes with one shared start, width and step
  sequencer; the two sample inputs and bit orders stay independent. The block
  flags conflicting starts, steps or start widths as incompatible and freezes
  while the request is incompatible. The environment must inspect that signal.
* `pair_combined_independent`: one wrapper around the same two independent
  lanes. This tests packaging only; it intentionally does not claim an
  optimized implementation or shared logic. Synthesis flattens the wrapper.

The matched, hand-authored stimulus is taken from the source requirements,
not generated by the CIRCT compiler:

1. A JTAG-like 8-bit transfer sends `scan8(0x80, 0x5a)` with different TMS and
   TDI patterns, uses shared start and step events, and samples an independent
   `0x3c` TDO pattern. An independent scoreboard checks each output bit, sample
   word and completion. All three candidates agree on the shared-control case.
2. An I2C-like byte phase starts only one lane, sends an MSB-first `0xa5`
   followed by a released ninth bit, and externally suppresses four step events
   to represent a clock-stretch hold. The independent candidates retain the
   bit during the hold and accept the one-lane operation; the shared candidate
   reports incompatible independent start and step controls.
3. A directed control case starts both lanes with different lengths and rates;
   the independent lanes complete separately, and the shared block rejects the
   unequal widths. This is a general capability test, not a claim that the
   checked-in I2C transaction requires these exact concurrent rates.

The I2C check models wired-low SCL/SDA and manually gates the step input: it
does **not** instantiate the source program, a timer, input synchronizer or a full I2C peer, and
it does not prove clock-stretch response or sample timing. Likewise the JTAG
check is a scan stimulus, not the complete TAP test. The nine-bit byte phase
is one implementation of the source behavior; it does not prove that a shared
block with different controls or scheduling cannot implement I2C. No selector
or interconnect area is included.

On this checkout, Yosys `0.67+111 (4821ed17b-dirty)` with flattened generic
synthesis reports:

| Candidate | Generic cells | Flip-flops |
| --- | ---: | ---: |
| Separate | 238 | 78 |
| Combined, shared sequencer | 218 | 71 |
| Combined, independent sequencers | 238 | 78 |

These are generic cell counts, not standard-cell area, silicon area, delay,
power, congestion, or a matched full-fabric result. The shared candidate has
a smaller functional contract, so this is not a same-coverage cost win. The
identical independent result follows from using the same lanes under a wrapper.
Timer, I/O, configuration, host/storage and route costs are excluded.
